# 05 — Launch SOP: the first 14 days

The first two weeks decide whether this account ever works. Almost all of the discipline
required is *not doing things*.

---

## The launch window

| Day | Launch? | Why |
|-----|:-------:|-----|
| Monday | ❌ **Never** | Linda's lowest converting day. Your first 24h of learning data would be her worst behaviour |
| Tuesday | ⚠️ Avoid | Still in "back to the week" mode |
| Wednesday | ⚠️ Acceptable | |
| **Thursday** | ✅ **Best** | She's mentally checking out of the week; full weekend runway |
| **Friday** | ✅ **Best** | |
| **Saturday** | ✅ Good | Peak unstructured scroll |
| Sunday | ⚠️ Acceptable | Fine, but a Monday sits in the middle of your first learning window |

**Time of day:** publish 8:00–10:00 AM ET so the first calendar day gets full delivery hours
— including her 11 AM window.

---

## T-minus checklist

### T−7 days
- [ ] File 01 gates all green (especially **EMQ ≥ 7.0**)
- [ ] File 02 worksheet complete with real numbers; the seven numbers written down
- [ ] Creative brief issued for all five Rings (file 08)
- [ ] Landing pages briefed (file 09)

### T−3 days
- [ ] All 5 CONTROL assets delivered and QA'd (file 03 §10)
- [ ] TEST-A 3:2:2 pack delivered (3 creatives, 2 texts, 2 headlines)
- [ ] TEST-B 3:2:2 pack delivered *(T2+ only)*
- [ ] Landing pages live, tested on **iPad**, Apple Pay/Shop Pay enabled
- [ ] Stock confirmed for a 30-day run at forecast volume ← *a stockout mid-learning is
      unrecoverable; you lose the learning and the reviews*

### T−1 day
- [ ] Campaign built per file 04, **not published**
- [ ] Step 6 pre-publish verification 100% ticked
- [ ] Budget math verified: CONTROL remainder ≥ $58
- [ ] Backup payment method on file
- [ ] Tracker sheet created (`templates/tracker-spec.md`)
- [ ] Calendar blocks set: **launch+4** (first read), **launch+11** (first Monday Review)

### Launch day
- [ ] Publish before 10 AM ET
- [ ] All ad sets Active within 24h
- [ ] Impressions serving on all three within 2h
- [ ] End-to-end tracking test completed (file 04 §8)
- [ ] Launch row written into the tracker
- [ ] **Freeze declared** — tell everyone with account access, in writing

## Day-by-day: the first 14 days

| Day | What you do | What you must NOT do |
|-----|-------------|----------------------|
| **0** | Publish. Verify delivery + tracking | Everything else |
| **1** | Confirm all ad sets spending. Confirm no rejections | Look at CPA. It is meaningless today |
| **2** | Same 60-second check | Judge any creative |
| **3** | Same. Note if any ad set is dramatically under-delivering *(a delivery bug, not a performance read)* | Pause anything |
| **4** | **First read.** Record CPM, CTR, hook rate, spend distribution. **Observation only** | Act on any of it |
| **5–6** | Nothing. Weekend | Weekend panic. Weekends read differently |
| **7** | 7 days complete. Record the full week's baseline into the tracker | Still no structural changes |
| **8–10** | Nothing. Let the second week accumulate | |
| **11** | **First Monday Review** (file 06). Now you may act | Act on anything not in the threshold table |
| **12–13** | Execute whatever the Review decided — usually: one budget step, or one new test asset briefed | Add a second change |
| **14** | Two full weeks of clean data. The system is now running normally | — |

## What "normal" looks like on day 4

Use this to distinguish *a bad account* from *a young account*. Almost every new account
looks alarming on day 4.

| Observation on day 4 | Verdict |
|----------------------|---------|
| "Learning limited" on some or all ad sets | ✅ **Expected.** See file 02 §5 |
| CPA 2–3× target | ✅ **Expected.** Learning-phase CPA is not real CPA |
| One ad taking 60% of CONTROL's spend | ✅ **Expected and good.** Meta has an opinion. Let it |
| One Ring at zero spend | ⚠️ Note it. Do nothing until day 11 |
| Test ad set spending exactly its $58 minimum and no more | ✅ Normal. The floor is working |
| Test ad set spending **above** its minimum | ✅ **Excellent.** Meta is choosing it |
| Frequency > 2.0 already | ⚠️ Check your exclusions actually applied |
| Zero purchases account-wide after $150 spend | ⚠️ Check the pixel, not the creative. Run a live test purchase |
| CPM $60+ | ⚠️ Check EMQ, check for a seasonal spike, check the audience isn't accidentally narrowed |
| An ad rejected | Handle per file 04 §7. Don't let it delay the others |

**The only day-4 findings that justify acting immediately** are *technical*: tracking not
firing, an ad set not delivering at all, a rejected ad, or a stockout. Never performance.

---

## Emergency stop conditions

The freeze has exactly four exceptions. Nothing else qualifies.

| Condition | Action |
|-----------|--------|
| **Pixel/CAPI stopped firing** | Pause the campaign. Fix. Relaunch. You are buying blind |
| **Stockout or fulfilment failure** | Pause the campaign. Do not sell what you can't ship |
| **Compliance / legal issue with a claim** | Pause the offending ad only |
| **Runaway spend from a misconfiguration** (e.g. budget entered as $1,000 instead of $100) | Fix the budget. Do not pause the campaign |

"CPA looks bad" is not on this list. It will never be on this list.

---

## Handover: what to tell a stakeholder who wants an update on day 3

Have this ready, because the question always comes.

> "We launched Thursday. The campaign is in Meta's learning phase, which lasts until roughly
> 50 purchases per ad set — around day 10–14 at this budget. Any CPA number before then is
> noise, because Meta is deliberately buying exploratory impressions to build its model.
> We're tracking delivery and tracking health daily, and the first real performance read is
> [date, launch+11]. Touching the account before then throws away the data we've paid for
> and restarts the clock."
